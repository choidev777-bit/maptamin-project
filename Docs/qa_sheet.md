
# 🧪 브라우저 QA 시트 (Browser QA Sheet)

이 문서는 개발된 기능이 실제 브라우저에서 사용자의 의도대로 잘 동작하는지 검증하기 위한 테스트 시나리오입니다.
**비개발자**의 관점에서 "정상적인 기능 수행(Happy Path)"과 "예외 상황(Negative Path)"을 모두 다룹니다.

---

## 🧐 QA 기준 (Testing Criteria)

다음 4가지 기준을 중점으로 확인해주세요.

1.  **기능성 (Functionality)**: 버튼을 눌렀을 때 약속된 동작(페이지 이동, 데이터 저장 등)을 수행하는가?
2.  **데이터 흐름 (Data Flow)**: A페이지에서 입력한 데이터나 상태가 B페이지로 올바르게 전달되는가?
3.  **예외 처리 (Error Handling)**: 사용자가 실수하거나 권한이 없을 때(예: 삭제 불가 기간) 적절한 안내 메시지가 나오는가?
4.  **UX 편의성 (Usability)**: 로딩 표시(Spinner), 버튼 반응 등 사용자가 불편함을 느끼지 않는가?

## ✅ 2. 경쟁사 관리 (Competitor Management)

*진입 경로: 경쟁사 순위 검색 > 네이버 지도 검색*

| 테스트 항목 | 기대 결과 (Expected Result) | 확인 |
| :--- | :--- | :--- |
| **빈 슬롯 확인** | 등록된 경쟁사가 없을 때, 빈 카드("경쟁사 추가")가 표시된다. | [x] |
| **경쟁사 등록 (API)** | "+" 버튼 -> 모달 검색 -> 선택 후 "확인" 시, 새 카드가 즉시 생성된다. (새로고침 없이) | [x] |
| **30일 락(Lock) 확인** | 방금 등록한 경쟁사 카드에 "30일간 변경 불가" 뱃지 혹은 잠금 아이콘이 표시된다. | [x] |
| **삭제 시도 (방어 로직)** | 잠금된 경쟁사의 "휴지통" 아이콘을 누르면, "삭제할 수 없습니다(LOCKED)" 경고창이 뜬다. | [x] |
| **슬롯 제한 확인** | (가능하다면) 4개 이상 등록 시도 시 "최대 개수 초과" 에러 메시지가 뜬다. | [ ] |

## ✅ 3. 순위 검색 연결 (Search Flow)

| 테스트 항목 | 기대 결과 (Expected Result) | 확인 |
| :--- | :--- | :--- |
| **자동 입력 연결** | 경쟁사 카드의 **"순위 검색 (돋보기)"** 버튼을 클릭한다. | [x] |
| **페이지 이동** | 네이버 검색 페이지로 이동하며, 제목이 **"경쟁사 순위 조회"**로 표시된다. | [x] |
| **데이터 프리필(Prefill)** | 비즈니스 선택 단계에서 해당 경쟁사의 이름과 주소가 **이미 선택된 상태**여야 한다. | [x] |
| **다음 단계 진행** | 별도 입력 없이 "다음" 버튼을 눌러 키워드 입력 단계로 넘어갈 수 있다. | [x] |
