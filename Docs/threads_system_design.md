└──────┬──────────┬──────────┬──────────┬──────────┬──────────────┘

## 모듈 1: 소재 수집기 (Collector)

### 목적
스레드, 유튜브, X(트위터)에서 콘텐츠를 자동 수집하여 소재 DB에 저장

### 수집 소스별 프로세스

#### 1-A. 스레드 피드 수집 (텍스트 폼) — 혼합 방식

> 일반 피드에서는 **카테고리 무관한 터지는 패턴(틀)**을 배우고,
> 키워드 검색에서는 **내 카테고리의 소재(내용)**를 수집

```
[수집 프로세스 — 3단계]

━━━ STEP 1: 피드 스크롤 수집 (클릭 없이 DOM만 읽음) ━━━

  A. 일반 피드 스캔 (For You 탭)
     - 목적: 카테고리 불문 터지는 글 패턴 발견
     - VPS의 Chrome CDP → 피드 자동 스크롤
     - 1회 스크롤 → 대기(2초) → 새 글 로딩 → 추출 → 반복
     - 1회 약 200개 수집 (약 20분)

  B. 키워드 검색 스캔 (Search 탭)
     - 목적: 내 카테고리 관련 소재 수집
     - 설정된 키워드로 스레드 검색 (예: "마케팅", "SEO", "자영업")
     - 검색 결과를 스크롤하며 수집
     - 1회 약 200개 수집 (약 20분)

  각 포스트에서 DOM으로 추출 (클릭 불필요):
     - 글 텍스트 (전문)
     - 좋아요 수 / 답글 수 / 리포스트 수
     - 작성자 이름 / 작성 시간
     - ★ 글 URL (threads.net/@username/post/XXXX)
  수집 데이터를 Supabase에 저장
  중복 체크 (동일 텍스트 해시로 판별)

━━━ STEP 2: 조회수 추출 (상위 글만 클릭) ━━━

  1. DB에서 좋아요 상위 50개 필터링
  2. 저장된 URL로 직접 이동 (피드 재검색 불필요)
     → https://threads.net/@kennenblog/post/abc123
     → 상단 "조회 9.9천회" 추출
  3. views 필드 업데이트
  소요 시간: 약 15분 (50개 × 글당 ~15초)

━━━ STEP 3: AI 카테고리 분류 ━━━

  수집된 전체 글을 AI에게 넘겨서 자동 분류:
  - "이 글은 마케팅? 맛집? 재테크? IT? 자기계발?"
  - 각 글에 category 태그 자동 부여
  - 내 카테고리에 맞는 글만 is_selected = true
  - 카테고리 다른 글도 패턴 분석용으로 보존
```

**트리거**: 매일 새벽 4시 Cron 자동 실행 + 대시보드에서 수동 실행 가능
```bash
# 일반 피드 스캔 (패턴 발견용)
0 4 * * * python3 /root/threads-api/scanner.py --mode feed --count 200

# 키워드 검색 스캔 (내 카테고리 소재용)
30 4 * * * python3 /root/threads-api/scanner.py --mode search --keywords "마케팅,SEO,자영업" --count 200
```

#### 1-B. 유튜브 롱폼 소재 수집

```
[수집 프로세스]

1. YouTube Data API로 키워드 검색 → 인기 영상 목록
2. youtube-transcript-api로 영상 자막(transcript) 자동 추출
3. AI에게 자막 요약 → 스레드용 소재 변환
   - 10~30분 영상에서 핵심 포인트 3~5개 추출
   - 스레드 텍스트 폼에 맞게 구조화
4. 변환된 소재를 DB에 저장 (source_type: 'youtube_long')
```

**트리거**: 매일 새벽 5시 Cron 자동 실행 + 대시보드에서 수동 실행 가능
```bash
0 5 * * * python3 /root/threads-api/youtube_collector.py --type long
```

#### 1-C. 유튜브 쇼츠 소재 수집

```
[수집 프로세스]

1. YouTube Data API로 키워드 검색 + 쇼츠 필터 (duration: short)
2. youtube-transcript-api로 자막 추출
3. 쇼츠는 60초 이내이므로 거의 그대로 스레드 글로 변환 가능
   - 자막 전문 → AI가 스레드 톤으로 리라이팅
4. 변환된 소재를 DB에 저장 (source_type: 'youtube_shorts')
```

**트리거**: 매일 새벽 5시 30분 Cron 자동 실행
```bash
30 5 * * * python3 /root/threads-api/youtube_collector.py --type shorts
```

#### 1-D. X(트위터) / 레딧 수집

```
[수집 프로세스]

1. 특정 키워드 또는 계정의 인기 포스트 수집
2. 텍스트 추출 + 참여 지표 수집
3. DB 저장
```

**트리거**: 추후 확장 (Phase 2 이후)

#### 1-E. 수동 소재 추가 (대시보드)

> 자동 수집 외에 직접 발견한 소재를 수동으로 등록하는 기능

```
┌─ 소재 수동 추가 ──────────────────────────────────┐
│                                                    │
│  소재 타입 선택:                                    │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌────────┐│
│  │ 📰 뉴스   │ │ 🧵 스레드 │ │ 📺 롱폼   │ │📱 쇼츠 ││
│  │  기사     │ │  글      │ │          │ │        ││
│  └──────────┘ └──────────┘ └──────────┘ └────────┘│
│                                                    │
│  입력 방식:                                        │
│  ○ 링크 붙여넣기  ● 텍스트 직접 입력                │
│                                                    │
│  ┌──────────────────────────────────────────────┐  │
│  │ https://... 또는 텍스트 직접 입력              │  │
│  │                                              │  │
│  │                                              │  │
│  └──────────────────────────────────────────────┘  │
│                                                    │
│  [➕ 소재 추가]                                     │
└────────────────────────────────────────────────────┘
```

**입력 타입별 처리:**

| 입력 | 처리 방식 |
|------|----------|
| **뉴스 링크** | URL 스크래핑 → 기사 본문 추출 → AI 분석 |
| **스레드 링크** | 해당 글 텍스트 추출 → DB 저장 |
| **유튜브 링크** | 자막 추출 → AI가 스레드용으로 변환 |
| **텍스트 직접 입력** | 바로 DB 저장 → AI 분석 |

**트리거**: 대시보드에서 수동 실행

### 소재 DB 스키마

```
raw_sources (소재 원본)
├── id                  UUID
├── source_type         ENUM: 'threads' | 'youtube_long' | 'youtube_shorts' | 'news' | 'x' | 'reddit'
├── input_method        ENUM: 'auto' | 'manual' (자동 수집 vs 수동 추가)
├── source_url          TEXT (원본 링크)
├── author              TEXT
├── text_content        TEXT (원문)
├── converted_text      TEXT (스레드용으로 변환된 텍스트, 유튜브 소재의 경우)
├── likes               INTEGER
├── replies             INTEGER
├── reposts             INTEGER
├── views               INTEGER (조회수, 상위 글만 수집)
├── engagement_score    FLOAT (자동 계산: 좋아요 + 답글×가중치 + 리포스트×가중치)
├── category            TEXT (카테고리 태그)
├── pattern_type        TEXT (분석 후 태그: A/B/C/D)
├── is_selected         BOOLEAN (검수 통과 여부)
├── collected_at        TIMESTAMP
└── analyzed_at         TIMESTAMP
```

## 모듈 2: 분석 엔진 (Analyzer)

### 목적
수집된 소재를 AI가 분석하여 패턴 분류, 서브 패턴 발견, 성과 점수를 추출

### 분석 프로세스 — 2단계

```
[PHASE 1] 개별 글 분류 — 각 글의 타입/카테고리 태그

[PHASE 2] 서브 패턴 발견 — 타입별 글 묶어서 세부 유형 분류
```

#### PHASE 1: 개별 글 분류 (JSON 요청/응답)

**AI에게 보내는 요청:**
```json
{
  "instruction": "아래 스레드 글들을 분석해서 각각 분류해줘",
  "categories": ["마케팅", "맛집", "재테크", "IT", "자기계발", "기타"],
  "types": {
    "A": "트래픽 유도 (짧고 자극적, 어그로, 논란)",
    "B": "인사이트 (정보, 체크리스트, 팁, 리스트)",
    "C": "신뢰/라포 (후기, 실적, 경험담, 스토리)",
    "D": "트렌드 (시사, 뉴스 반응, 타이밍)"
  },
  "posts": [
    {"id": "uuid-001", "text": "이거 모르면 사업 접어야...", "likes": 2300},
    {"id": "uuid-002", "text": "SEO 체크리스트 7가지...", "likes": 450},
    ...
  ]
}
```

**AI가 돌려주는 응답:**
```json
{
  "results": [
    {
      "id": "uuid-001",
      "type": "A",
      "category": "마케팅",
      "hook_style": "위협형",
      "target": "BROAD",
      "score": 9.2
    },
    {
      "id": "uuid-002",
      "type": "B",
      "category": "마케팅",
      "hook_style": "리스트형",
      "target": "NICHE",
      "score": 7.1
    }
  ]
}
```

→ 결과를 raw_sources 테이블에 자동 업데이트

#### PHASE 2: 서브 패턴 발견 (JSON 요청/응답)

> PHASE 1에서 분류된 타입A 글 50개, 타입B 글 30개... 를
> 각 타입별로 묶어서 AI에게 **"이 안에서 서로 다른 유형들을 찾아줘"** 요청

**AI에게 보내는 요청:**
```json
{
  "instruction": "아래는 모두 '타입A(트래픽 유도)' 글이야. 이 글들을 읽고 서로 다른 서브 패턴들을 찾아서 분류해줘",
  "required_output": {
    "pattern_name": "패턴 이름 (예: 위협형, 라벨링형)",
    "hook_template": "첫 줄 구조 (빈칸은 ___로 표시)",
    "body_structure": "본문 구조 설명",
    "cta_template": "마무리 구조",
    "example_ids": "해당 패턴에 속하는 글 ID 목록",
    "avg_likes": "해당 패턴 글들의 평균 좋아요"
  },
  "posts": [
    {"id": "uuid-001", "text": "이거 모르면 사업 접어야...", "likes": 2300},
    {"id": "uuid-005", "text": "자영업자 90%가 모르는...", "likes": 1800},
    ...
  ]
}
```

**AI가 돌려주는 응답:**
```json
{
  "parent_type": "A",
  "sub_patterns": [
    {
      "pattern_name": "위협형",
      "hook_template": "이거 모르면 ___ 못합니다",
      "body_structure": "이유 1~2줄 → 끝 (짧게 끊기)",
      "cta_template": "제 피드 보세요 / 댓글에 씁니다",
      "example_ids": ["uuid-001", "uuid-012", "uuid-034"],
      "avg_likes": 1850
    },
    {
      "pattern_name": "라벨링형",
      "hook_template": "___하는 사람 특징",
      "body_structure": "특징 3~5개 리스트",
      "cta_template": "없음 (그냥 끊기)",
      "example_ids": ["uuid-005", "uuid-019"],
      "avg_likes": 920
    },
    {
      "pattern_name": "고백형",
      "hook_template": "솔직히 말하면 ___",
      "body_structure": "반전 1줄 → 충격 사실",
      "cta_template": "어떻게 생각하세요?",
      "example_ids": ["uuid-008", "uuid-027", "uuid-041"],
      "avg_likes": 2100
    }
  ]
}
```

→ 결과를 patterns 테이블에 자동 저장

### 패턴 DB 스키마

```
patterns (패턴 라이브러리 — 서브 패턴 단위)
├── id                  UUID
├── parent_type         ENUM: 'A' | 'B' | 'C' | 'D'
├── pattern_name        TEXT (예: "위협형", "라벨링형", "고백형")
├── hook_template       TEXT (첫 줄 템플릿: "이거 모르면 ___ 못합니다")
├── body_structure      TEXT (본문 구조 설명)
├── cta_template        TEXT (마무리 템플릿)
├── example_source_ids  UUID[] (예시 소재 ID 목록)
├── avg_engagement      FLOAT (해당 패턴의 평균 참여)
├── usage_count         INTEGER (이 패턴으로 생성된 글 수)
├── success_rate        FLOAT (이 패턴의 실제 성과)
└── created_at          TIMESTAMP
```

## 모듈 3: 콘텐츠 공장 (Generator)

### 목적
학습된 패턴 + 소재를 기반으로 발행용 콘텐츠를 대량 생성

### 생성 프로세스

```
[콘텐츠 생성 파이프라인]

입력:
  - 패턴 라이브러리에서 선택한 패턴
  - 소재 DB에서 선택한 참고 소재
  - 계정별 브랜딩 설정 (톤, 주제, 금지어)

1. 대시보드에서 생성 요청:
   ┌─ 콘텐츠 생성 ──────────────────────────────────┐
   │                                                 │
   │  계정: [bono_marketing ▼]                       │
   │                                                 │
   │  소재 선택 (복수 선택 가능):                      │
   │  ┌─────────────┐ ┌──────────────┐ ┌───────────┐│
   │  │ 🧵 텍스트 폼 │ │ 📺 유튜브 롱폼│ │ 📱 쇼츠   ││
   │  │   ✅ 선택    │ │              │ │   ✅ 선택 ││
   │  └─────────────┘ └──────────────┘ └───────────┘│
   │                                                 │
   │  패턴: [TYPE_A 트래픽형 ▼]                       │
   │  생성 개수: [50]                                 │
   │                                                 │
   │  [🚀 생성하기]                                   │
   └─────────────────────────────────────────────────┘
   - 선택한 소재 타입에 해당하는 raw_sources만 참고하여 생성
   - 복수 선택 시 선택된 소재 타입을 혼합 활용

2. AI에게 배치 생성 요청 (product_brief 포함):
   ```json
   {
     "pattern": {
       "hook": "{hook_template}",
       "body": "{body_structure}",
       "cta": "{cta_template}"
     },
     "sources": ["{example_texts}"],
     "branding": "← accounts_config에서 자동 로드 (계정별 topic, tone, banned_words)",
     "product_brief": {
       "name": "맵타민 (Maptamin)",
       "description": "로컬 비즈니스 지도 순위 추적 SaaS",
       "features": [
         "네이버 지도 키워드 순위 자동 추적",
         "구글 지도 키워드 순위 추적",
         "주변 경쟁업체 순위 비교",
         "순위 변동 알림"
       ],
       "related_topics": ["네이버 지도 상위노출", "구글 지도 SEO", "로컬 SEO", "가게 마케팅", "지도 순위"],
       "link": "https://maptamin.com",
       "link_comment_templates": [
         "내 가게 순위 확인해보세요 → maptamin.com",
         "키워드별 순위 자동 추적 → maptamin.com"
       ]
     },
     "link_instruction": "글 내용이 product_brief.related_topics와 자연스럽게 연결되면 link_eligible: true로 표시하고, 그 글에 맞는 댓글 문구도 생성해줘",
     "count": 50,
     "max_chars": 500
   }
   ```

3. AI 출력 → contents 테이블에 저장 (status: 'draft')

4. 대시보드에서 사람이 검수:
   - 각 글 읽고 ✅ 승인 / ✏️ 수정 / ❌ 삭제
   - 승인된 글은 status: 'approved'
   - 발행 순서 지정 (드래그앤드롭)

5. 승인된 글 → 발행 대기열로 이동 (status: 'queued')
```

### 콘텐츠 DB 스키마

```
contents (생성된 콘텐츠)
├── id                  UUID
├── account             ENUM: 'bono' | 'place'
├── text_content        TEXT (발행할 글)
├── parent_type         ENUM: 'A' | 'B' | 'C' | 'D'
├── pattern_id          UUID (FK → patterns)
├── source_ids          UUID[] (참고한 소재 ID)
├── status              ENUM: 'draft' | 'approved' | 'queued' | 'published' | 'failed'
├── link_eligible       BOOLEAN (AI가 판단: 제품과 관련 있는 글인지)
├── link_comment        TEXT (AI가 생성한 댓글 링크 문구, nullable)
├── scheduled_at        TIMESTAMP (발행 예정 시간)
├── published_at        TIMESTAMP (실제 발행 시간)
├── thread_post_id      TEXT (발행 후 스레드 게시물 ID)
├── engagement          JSONB {likes, replies, reposts, views}
├── created_at          TIMESTAMP
└── reviewed_by         TEXT ('human' | 'auto')
```

## 모듈 4: 발행 스케줄러 (Publisher)

### 목적
승인된 콘텐츠를 정해진 시간에 Threads API로 자동 발행

### 발행 프로세스

```
[자동 발행 파이프라인]

트리거: Cron (2시간마다)

1. contents 테이블에서 조건 조회:
   - status = 'queued'
   - scheduled_at <= NOW()
   - account별 오늘 발행 횟수 < 일일 한도

2. 계정별로 다음 발행할 글 1개 가져오기

3. Threads API로 발행:
   ┌──────────────────────────────────┐
   │  Step 1: 컨테이너 생성            │
   │  POST /{user_id}/threads         │
   │  → creation_id 획득              │
   │                                   │
   │  Step 2: 게시                     │
   │  POST /{user_id}/threads_publish  │
   │  → post_id 획득                  │
   │                                   │
   │  Step 3: 댓글 링크 (콘텐츠 기반)     │
   │  if link_eligible == true:        │
   │    POST /{post_id}/replies        │
   │    → link_comment 내용으로 댓글    │
   └──────────────────────────────────┘

4. 결과 업데이트:
   - status → 'published'
   - published_at → NOW()
   - thread_post_id → 발행된 게시물 ID

5. 텔레그램 알림 전송:
   "✅ [bono] 발행 완료: 글 미리보기..."

6. 실패 시:
   - status → 'failed'
   - 텔레그램 알림: "❌ 발행 실패: 에러 내용"
   - 3회까지 재시도
```

### 발행 규칙

```
계정 설정 (accounts_config) ← 대시보드에서 관리

├── display_name        TEXT ("bono_marketing" | "place_hacker_")
├── topic               TEXT (계정 주제)
├── tone                TEXT (말투 스타일)
├── scan_keywords       TEXT[] (스캔용 키워드 목록)
├── banned_words        TEXT[] (금지어 목록)
├── interval_hours      INTEGER (기본: 2)
├── daily_limit         INTEGER (기본: 6)
├── active_hours_start  INTEGER (기본: 8 = 오전 8시)
├── active_hours_end    INTEGER (기본: 23 = 오후 11시)
├── is_active           BOOLEAN
└── updated_at          TIMESTAMP

확정된 계정 프로필:

│  place_hacker_                                        │
│  주제: 네이버 플레이스/구글 지도 상위노출               │
│  말투: 시크, 도도                                      │
│  키워드: [네이버 플레이스, 구글 지도, 상위노출, 지도 순위, 로컬 SEO] │

└───────────────────────────────────────────────────────┘

제품 연동 설정 (product_config) ← 대시보드에서 관리
├── id                  UUID

```

### 템플릿 타입 정의

```
타입 A: 트래픽 유도 (어그로)
  구조: 후킹 1줄 → 본문 2~3줄 → 끝 (짧게)
  톤:  자극적, 단정적, 논란 유발
  예시: "이거 모르면 사업 접어야 합니다"

타입 B: 인사이트 (정보)
  구조: 후킹 1줄 → 숫자 리스트 3~7개 → CTA
  톤:  전문가, 유익함, 소장 가치
  예시: "네이버 지도 상위노출 체크리스트 7가지"

  구조: 뉴스/이슈 언급 → 나의 관점 → 행동 촉구
  톤:  빠른 반응, 의견 제시
  예시: "네이버가 AI 검색 도입한다고 합니다"
```

### 발행 사이클 패턴

```

### 피드백 루프 (패턴 자동 진화)

```
┌─────────────┐
│  매일 스캔   │ 스레드 피드 + 유튜브 → 새 소재 수집
└──────┬──────┘
       ▼
┌─────────────┐
│  AI 분석    │ 새 패턴 발견 → 패턴 라이브러리 업데이트
└──────┬──────┘     + 트렌드 감지 시 텔레그램 알림
       ▼          "🔥 새 트렌드: OO 관련 글 급증 중!"
┌─────────────┐
│  콘텐츠 생성 │ 업데이트된 패턴 기반 글 생성
└──────┬──────┘
       ▼
┌─────────────┐
│  자동 발행   │ 2시간마다 Threads API 발행
└──────┬──────┘
       ▼
┌─────────────┐
│  성과 수집   │ 발행된 글의 좋아요/답글/리포스트 추적
└──────┬──────┘
       ▼
┌─────────────┐
│  패턴 평가   │ 어떤 패턴이 잘 터졌나?
│             │  - 잘 된 패턴: 비중 ↑
│             │  - 안 된 패턴: 비중 ↓ 또는 도태
│             │  - 새 패턴: 추가
└──────┬──────┘
       │
       └──────→ 다시 맨 위로 (매일 반복)
```
